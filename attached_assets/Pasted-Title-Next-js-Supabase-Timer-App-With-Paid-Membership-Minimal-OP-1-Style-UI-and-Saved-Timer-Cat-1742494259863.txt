Title: Next.js + Supabase Timer App With Paid Membership, Minimal OP‑1-Style UI, and Saved Timer Categories

Description:
Please generate a secure, production-ready Next.js application that integrates with Supabase for authentication, data storage, and membership gating. The app should feature:

Paid Membership Gate

Include a membership system (Stripe or similar) enabling “paid” members to unlock two advanced features:
Analytics Dashboard: Displays charts, aggregated stats, and historical logs.
Persistent Session Data: Paid members can save multiple timer records and retrieve them.
If a user is not a paid member, they can still use the basic timer but are denied access to advanced analytics and the ability to save sessions. Show an upgrade prompt or CTA for unsubscribed users.
Use best practices for verifying membership status on the server side (e.g., a role or is_subscribed column in Supabase). Ensure all sensitive operations are protected by Row Level Security (RLS) policies or membership checks.
Timer Categories with Templates

Provide a user-defined category system for timers.
Include a default list of template categories (e.g., “Work,” “Study,” “Exercise,” “Break”).
Let users select from these preloaded categories in a dropdown, as well as create, save, and reuse their own categories.
For free users, store categories temporarily. For paid members, persist categories in the database (Supabase) so that they are saved across sessions.
Minimalist, OP-1-Inspired UI

Make the interface minimal, reminiscent of Teenage Engineering’s OP‑1 design. Use large, bold typography, plain shapes, and limited but tasteful color usage.
Provide an easy way for the user to customize the color scheme (e.g., theme toggles, background color pickers, or a few preset minimal themes).
Keep the layout clean and consistent with accessibility guidelines (sufficient color contrast, ARIA labels for interactive elements, semantic HTML structure).
Core Timer Functionality

Provide standard countdown timer, stopwatch, and pomodoro modes.
For each mode, let users specify or choose a category. If user is paid, store session data to Supabase (with the user’s ID). If not, store only client-side (or do not store at all) and display a CTA to upgrade to save data.
Incorporate best practices for code readability, safe user input validation, and minimal overhead.
Supabase Setup

Create a users table if it does not already exist (or use the built-in auth.users).
Create a focus_sessions table that references the user’s ID.
Add a boolean or membership field (e.g., is_subscribed) on the user’s profile row.
Protect these tables with Row Level Security.
Write example migration scripts or SQL to illustrate membership gating: if the user’s is_subscribed = true, allow access to analytics and session inserts; otherwise, block.
Provide secure custom endpoints (Next.js API routes) or direct client usage of Supabase for reading/writing session data. Validate membership on the server side to avoid client spoofing.
Analytics & Data Visualization

When a user is paid, show an “Analytics” or “Statistics” page with aggregated data:
Total time spent in a category.
Charts showing distribution of durations by category or day-of-week.
Access to saved session logs with pagination.
Use a minimal charting solution (like @mui/x-charts or similar).
Secure & Performant

Thoroughly comment your code so it is readable and follows industry standards.
Use Next.js best practices: SSR or server actions for sensitive data, client-side code only for non-sensitive UI.
Carefully handle user authentication, ensuring no membership data is revealed to unauthorized users.
Include recommended environment variables, with placeholders for Supabase and any payment provider credentials.
Bonus:

Provide an environment setup that includes scripts for linting, testing, and building.
Add optional notifications or webhooks (e.g., membership renewal or expiration) to handle membership status changes.
Important Implementation Details:

Use Next.js 13+ (app router) or newer.
For styling, keep everything minimal and cohesive with OP‑1-like design. Minimal color palette, accessible text.
Keep the code modular: separate membership logic from timer logic.
For best security, all membership checks must happen server-side.
Provide user-friendly errors and fallback UIs for blocked features.
Requested Output:

A complete, ready-to-run Next.js project structure.
All relevant files: page.tsx for each route, Supabase row-level security policies, minimal MUI (or Tailwind) styling consistent with the OP‑1 aesthetic, and a Stripe (or placeholder) membership integration.
Comments explaining design and security decisions, following recommended best practices for accessibility, readability, and maintainability.
Once generated, the code should be thoroughly reviewed for potential improvements or vulnerabilities.
